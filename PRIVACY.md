# Privacy and local data

MaiBadges stores role fields, duties, avatar files, explicit title bindings, card position and display preferences in the selected local state directory. The default is `~/Library/Application Support/MaiBadges`. State includes a SQLite database, assets, configuration and diagnostic files.

The project does not operate a cloud storage service, telemetry endpoint, advertising system or payment service. The local MCP server communicates with its host over stdio. This does not mean that everything stays outside the host's services: structured role data returned by tools can be included in the host's chat context and processed under that host's own settings and policies. Image data supplied to an app view is also available to its host environment. Do not put secrets in role descriptions or duties.

When explicitly enabled, the optional loader connects only to a configured loopback CDP endpoint. Its context matching uses target metadata and the complete window/document title. In 0.8.0, sidebar decoration also reads recognizable navigation rows, including their titles and navigation identifiers, to match user-confirmed bindings. It does not collect chat message bodies. It sends the role display data and avatar assets needed for the floating badge and bound sidebar rows into the registered page. Unbound, disabled, ambiguous or unrecognizable rows are left unchanged. A CDP endpoint itself has broader debugging powers; the project's limited behavior does not reduce the endpoint's general authority.

In-memory image and card caches are bounded and belong to the running session. Reusing unchanged display data avoids redundant work; it does not create a cloud backup or permanent photo store. Persistent role data remains in the local state directory until the user removes it. The 0.8.0 upgrade keeps roles, avatars and bindings when the same state directory is used. Stopping or uninstalling the plugin preserves that directory; follow [INSTALL.md](INSTALL.md) to disable the loader and remove owned entries first.

Public example assets contain generic geometric artwork. Private team portraits, personal branding, signature fonts, production databases and real chat bindings are not distributed with the public package. Images users add to their own installations are not submitted to the project by the loader.

Diagnostics may contain paths, target titles, timestamps and error details. Review and redact them before sharing. There is no automatic deletion schedule or remote erasure service. To delete local data, first stop all users of the selected state directory, back up anything you need, then remove only the directory you have verified.
